**What it shows.** One line per kernel family — single-threaded CPU (`serial`), multi-threaded CPU (`parallel`), `amx` and `gpu` — at every matrix size, at the selected precision. Each point is the family's best result at that size: whichever kernel, thread count and block size was fastest. Both axes are logarithmic.

**How to read it.** The dashed lines are the hardware's theoretical peaks, from `data/peaks.csv`, in each family's colour: one performance core for `serial`, all the performance cores for `parallel`, and the whole GPU for `gpu`. Hover a point for the kernel and thread count behind it and its % of peak. The gap between a line and its ceiling is the performance left on the table.

**Caveats.** GPU timings are end-to-end: they include copying the matrices into and out of the GPU's buffers, the same host-to-host scope as the CPU timings. AMX has no published peak and the integer precisions no sourced one, so they get no ceiling. The `parallel` family's best result is often a run that also uses the efficiency cores, which its ceiling doesn't count, so it reads slightly high against it. A ceiling is drawn only when all of a family's points come from one device.
