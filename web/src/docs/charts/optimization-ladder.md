**What it shows.** One bar per optimization technique, in the order a programmer reaches for them: the textbook loop (`naive-ijk`), better single-core code, threads, Apple's AMX coprocessor, then the GPU. Each bar is the fastest result that technique produced at the selected precision, whatever kernel, thread count and block size got it there. Every bar is read at one matrix size, the largest N that every technique measured; the line above the chart names it, with the total speedup from the first rung to the last.

**How to read it.** Each bar's label gives the kernel behind it, its throughput, and × — how many times faster it is than the rung above. The x-axis is logarithmic, so equal differences in bar length are equal multipliers.

**Caveats.** The rungs stay in effort order, never sorted by speed: a technique that is slower than the one above it shows a multiplier below 1 rather than moving up. A technique with no results at this precision is left out (there is no GPU kernel at `f64` and no AMX kernel for the integer types), so the ladder can have fewer rungs. The `serial` rung doesn't count `naive-ijk`, which is its own rung.
