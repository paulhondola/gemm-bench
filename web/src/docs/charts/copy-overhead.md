**What it shows.** For each GPU kernel at each size, the share of its end-to-end time spent outside the GPU's own execution: copying the inputs into the GPU's buffers, encoding the work, the fixed latency of submitting it and waking the waiting CPU thread when it finishes, and copying the result back out.

**How to read it.** The copies grow as N² while the arithmetic grows as N³, so at large N the share falls as the computing takes over. At the smallest sizes the share approaches 100% for a different reason: the GPU finishes in microseconds, and the fixed dispatch latency (about 0.2 ms on an M1 Pro) dominates the round trip.

**Caveats.** The GPU's own time (`gpu_ms`) is the median of the command buffer's GPU timestamps over the same timed runs as the end-to-end time. Runs recorded before `gpu_ms` came from those timestamps timed `commit` → `waitUntilCompleted` on the CPU, which counts the dispatch latency as GPU time, so their small-N shares read far lower; rerunning the Metal kernels replaces them. The CPU and GPU share memory on Apple Silicon, so these copies stay within the same RAM rather than crossing a bus. The axis starts at 0 but isn't clamped there, so a negative share in contributed data stays visible.
